# 8월 8일 작업 기록 — VisualizationFlow 완성

`src/visualize/VisualizationFlow.ts`의 `run()`(현재 `throw` 스텁)을 채워 시각화 파이프라인
전체를 조립한다. 개별 클래스(PCA/Visualization/GraphData)는 007.md에서 이미 구현됨.
이 문서는 run()을 짜는 데 **필요한 것**과 **정할 것**을 정리한다.

## run()이 조립할 흐름 (007.md 확정)

```
run():
  papers = File.readAllPapers()      // 저장된 논문 전부 로드
  pca    = this.pca.run(papers)      // PCAResult (PCAError는 그대로 전파)
  graph  = this.visual.init(pca)     // GraphData 생성·반환 (container는 setContainer로 이미 담김)
  for (mw of visual 미들웨어) await mw.run(graph)   // GraphData 변형(색/엣지/이벤트 등)
  this.visual.render(graph)          // graph.container에 렌더
```

## 필요한 것 (이미 다 있음 — 확인됨)

- **논문 로드**: `File.readAllPapers()` — `PaperGraph3D/` 전체의 `.json`을 읽어 `Paper[]`.
  (연도 지정이 필요하면 `File.readPapersByYear(year)`도 있음. 시각화는 전체가 기본이라
  `readAllPapers` 사용.)
- **PCA**: `this.pca.run(papers): PCAResult`. 축을 내부 캐시하므로 논문이 늘어도 기존 점은
  제자리. 유효 논문 부족 시 `PCAError`를 던진다.
- **Visualization**: `this.visual.init(pca): GraphData` / `this.visual.render(graph)`.
  컨테이너는 뷰가 `this.visual.setContainer(div)`로 미리 등록한다.
- **미들웨어**: `this.middlewares: Middleware[]`, `Middleware.run(context)`의 context가
  여기선 `GraphData`.

→ VisualizationFlow에 `File`·`GraphData` import 추가만 하면 된다.

## 정할 것 (구현 전 확인)

1. **미들웨어 필터링**: `Middleware.type`은 `'all' | 'forEach' | 'visual'`. run()에서
   **`type === 'visual'`만 실행**할지, 아니면 `setMiddleware`에 등록된 건 전부 visual
   전제로 그냥 다 실행할지.
   - 추천: **run에서 `type === 'visual'`만 실행**(방어적). 잘못 등록돼도 시각화 흐름에
     엉뚱한 미들웨어가 안 끼어든다.
2. **PCAError 전파**: 유효 논문 부족/전부 동일 임베딩이면 PCA가 `PCAError`를 던진다. run은
   **삼키지 말고 그대로 올린다**(재수집 여부는 main/뷰가 판단 — 8/1 회의 합의). → run 안에
   try/catch로 감싸지 않는다. (확정 성격)
3. **빈 데이터**: `readAllPapers()`가 `[]`면 PCA가 `PCAError`를 던져 위 2번대로 전파된다.
   뷰가 "논문 없음/재수집" 안내를 띄운다. (별도 처리 불필요)
4. **basis 재사용**: run()은 `pca.resetBasis()`를 **부르지 않는다**(기존 점 안정성 유지).
   다른 코퍼스로 갈아탈 때만 호출자가 별도로 reset. (확정 성격)
5. **setContainer 선행 계약**: `render`가 `graph.container`를 쓰므로, run() **전에** 뷰가
   `this.visual.setContainer(div)`를 반드시 호출해야 한다. 안 하면 render에서
   "container 없음" 에러. → 뷰 배선(VisualizationView)에서 지킨다.

## 제안 구현 스케치

```ts
async run(): Promise<void> {
  const papers = await File.readAllPapers();
  const pca = this.pca.run(papers);          // PCAError는 잡지 않고 전파
  const graph = this.visual.init(pca);
  for (const mw of this.middlewares) {
    if (mw.type === 'visual') {
      await mw.run(graph);
    }
  }
  this.visual.render(graph);
}
```

## 뒤이어 할 것 (VisualizationFlow 밖)

- **VisualizationView 배선**: 뷰가 그래프용 div 생성 → `visual.setContainer(div)` →
  `await visualflow.run()`. (지금은 init/render를 각각 누르는 임시 버튼 상태.) run()이
  `PCAError`를 던지면 뷰가 잡아 Notice로 안내.

## 열린 항목

- 없음 — 미들웨어 필터링 `type === 'visual'`만 실행, 인자 GraphData로 확정(2026-08-08).

## 진행한 작업 (구현)

- `src/visualize/VisualizationFlow.ts`: `run()` 구현 — `File.readAllPapers()` → `pca.run`
  → `visual.init` → `type === 'visual'` 미들웨어에 `graph` 전달 → `visual.render`.
  `File` import 추가. PCAError는 잡지 않고 전파.
- `src/adapter/VisualizationView.ts`: **뷰를 최소화** — 열면(`onOpen`) 그래프용 div
  (`papergraph3d-graph`) 생성 → `visual.setContainer(div)` 등록(뷰 열 때마다 재등록) →
  **바로 `run()` 자동 실행**해 그래프를 그린다. 버튼·단계 UI 없음. 실패 시(`PCAError` 등)
  컨테이너에 메시지 표시.
  - ⚠️ 기존 **PCA 테스트 칸(합성 데이터 검증 버튼 등)을 제거**했다 — 그 블록 주석에
    "수집 파이프라인이 완성되면 이 블록 전체를 삭제한다"고 명시돼 있었고, 이제 파이프라인이
    연결돼 실데이터 그래프가 그 역할을 대체한다. (PCA 담당과 공유 필요 시 참고.)
- `styles.css`: `.papergraph3d-graph`(width 100% / height 600px) 추가.
- **미검증**: 빌드는 지시 시. 3d-force-graph/three 번들 + Obsidian WebGL 렌더는 빌드·실행 확인 필요.

## 뷰 동작 추가 (2026-08-08)

- **메인 탭에서 열기**: `main.ts activateVisualizationView`가 `getRightLeaf`(사이드 패널)
  대신 `workspace.getLeaf(false)`(현재 메인 탭)로 뷰를 연다.
- **마우스 조작 = OrbitControls**: `Visualization.render`에서 3d-force-graph를
  `new ForceGraph3D(container, { controlType: 'orbit' })`로 생성. orbit 매핑은
  **좌클릭 드래그=회전, 우클릭 드래그=이동(pan), 휠=줌**. (OrbitControls가 캔버스의
  우클릭 컨텍스트 메뉴를 자체적으로 막아 우드래그 pan이 정상 동작.)
