## 2026-08-03 확정 사항

### Secret — API 키 저장 구조: 맵(`Record<string, string>`)으로 결정

- **결정**: API 키를 개별 변수(named field)로 나열하거나 순수 `string[]`로 관리하지 않고,
  "API 식별자 → 키" 형태의 맵(`Record<string, string>`)으로 저장한다.
- **근거**:
  1. **확장성** — 이 프로젝트는 개발자가 API/미들웨어를 얹어 확장하는 프레임워크가
     목표(001.md 합의). 새 API가 추가될 때마다 `Secret` 클래스를 수정해야 하는
     named field 방식은 확장 지점과 충돌한다.
  2. **키-API 식별** — 다이어그램상 `Subscriptions`가 `API apis`(리스트)를 들고 있어,
     각 API가 "자기 키"를 꺼내려면 식별자가 필요하다. 순수 `string[]`는 순서(index)에
     의존해 구독 추가/삭제로 순서가 틀어지면 깨진다. 맵은 provider 식별자로 조회하므로
     순서와 무관하다.
  3. **직렬화** — `File`이 Secret.json으로 저장/로드할 때 `Record`가 그대로 JSON 객체로
     직렬화돼 매핑이 깔끔하다.
  4. **UI 배선** — SettingTab의 "API 키 입력" UI도 provider별로 `setKey`를 호출하면 되어
     자연스럽다.
- **예상 형태** (구현 시 확정):
  ```ts
  export class Secret {
    private apiKeys: Record<string, string> = {};
    getKey(provider: string): string | undefined { return this.apiKeys[provider]; }
    setKey(provider: string, key: string): void { this.apiKeys[provider] = key; }
  }
  ```
- **직렬화 책임 분담 (2026-08-03 확정, "일단 유지")**: `apiKeys`는 `private`으로 두고,
  Secret이 `toJSON()`/`static fromJSON()`으로 "객체 ↔ 평문 맵" 매핑을 소유한다. File은
  "평문 맵 ↔ 디스크 파일(JSON.stringify + vault I/O)"만 담당한다.
  - File은 이제 interface가 아니라 concrete static 클래스(`common/File.ts`)라 Secret을
    직접 import하지만, `apiKeys`가 private이므로 File이 직접 못 꺼낸다. 캡슐화를 유지하려면
    Secret이 접근자(`toJSON`)와 복원 경로(`fromJSON`)를 제공해야 한다.
  - 대안(File이 전부 직렬화 = `apiKeys` public화)도 검토했으나, `getKey`/`setKey` 통제와
    저장 포맷 소유권을 유지하기 위해 현재 방식을 유지하기로 함.

### Paper — 실제 저장 JSON 대조

실제 수집된 저장 파일(`schemaVersion: 3`)을 기준으로 현재 스텁 필드와 우리가 정한
(+)/(-) 수정안을 대조했다.

- 대조에 사용한 샘플: Obsidian Vault의 `PaperGraph3D/2025/11/07/…(2511.05319).json`
  (arxiv:2511.05319, "S^2LM: Towards Semantic Steganography via Large Language Models")

| JSON `paper` 필드 | 예시 값 | 현재 스텁 | 결정 |
|---|---|---|---|
| `title` | "$\mathbf{S^2LM}$…" | `title: string` | 유지 |
| `publicationYear` | 2025 | 없음(제거됨) | ✅ (-) 제거 확정 — `publicationDate`로 대체 |
| `publicationDate` | "2025-11-07" | 없음 | ✅ 유지 확정 (`string`, ISO 날짜) — `publicationYear` 대체 |
| `authors` | [6명] | `authors: string[]` | 유지 |
| `citationCount` | 0 | `citationCount: number` | 유지 |
| `abstract` | "Despite…" | `abstract: string` | 유지 |
| `sourceId` | "arxiv:2511.05319" | `sourceId: string` | 유지 |
| `references` | [] | `references: string[]` | 유지 |
| `embedding` | [768개 float] | 없음 | ✅ 유지 확정 — PCA/시각화 입력으로 필요 (`number[]`) |
| `embeddingModel` | "local-specter2-proximity-v1-d768" | 없음 | ✅ 유지 확정 (`string`) |
| `embeddingSource` | "local" | 없음 | ✅ 유지 확정 (`string`) |
| `embeddingFailure` | null | (교체 대상) | `embeddingSucceeded: boolean`으로 교체 (여기선 null→true) |
| `citationsKnown` | false | `citationsKnown: boolean` | 유지 (+) |
| — (JSON에 없음) | — | `collectedApi: string` | (+) 추가. 이 논문을 수집한 API 식별자. 실데이터엔 없어 수집 시 채움 |
| — (JSON에 없음) | — | `collectedQuery: SearchQuery` | (+) 추가. 수집에 쓰인 검색 쿼리(`searchType`+`query`). 수집 시 채움 |

- **`paper` 바깥의 래퍼 필드**(`schemaVersion`, `createdAt`, `updatedAt`,
  `readState`)는 파일/저장 레벨 메타데이터로 보고 Paper 클래스 밖(File 책임)으로 분류.

### 확정된 (+)/(-) 수정안 (다이어그램 회의 기준, 그대로 적용)

- (+) "어떤 방법으로 수집됐는가"의 재해석 (2026-08-03): recent/backfill 구분이 아니라
  **이 논문을 어떤 API로, 어떤 검색 쿼리로 수집했는가**를 뜻한다. 따라서 두 필드로 나눈다:
  - `collectedApi: string` — 수집한 API 식별자 (Secret 맵의 provider 키와 동일 체계).
  - `collectedQuery: SearchQuery` — 수집에 사용된 검색 쿼리(`searchType` + `query`).
  - recent/backfill은 Paper 필드가 아니라 `CollectAndSave.run()`의 실행 모드 인자로만
    존재한다 (다이어그램 run() 정의 참고). Paper에 저장하지 않는다.
  - ⚠️ 이 결정으로 Paper가 `SearchQuery`(신빈 담당)에 의존하게 됨 — 아래 열린 항목 참고.
- (+) `citationsKnown: boolean` — 인용수가 확인된 논문인가.
- 임베딩 성공/실패를 `embeddingFailure`(값/null 조합)에서 `embeddingSucceeded: boolean`
  T/F로 교체.
- (2026-08-03 확정) 임베딩 관련 값은 Paper에 유지한다: `embedding: number[]`(벡터),
  `embeddingModel: string`, `embeddingSource: string`. 시각화(PCA)가 벡터를 직접 쓰므로
  Paper가 들고 있는 게 맞다. `embeddingSucceeded`(성공 여부)와는 별개로 공존한다.
- (2026-08-03 확정) 발행 시점은 `publicationYear`(연도)를 제거하고 `publicationDate`
  (`string`, ISO 날짜 "2025-11-07")로 대체한다. 실데이터에 날짜까지 있어 더 정밀하고,
  연도가 필요하면 날짜에서 파생할 수 있다. 001.md의 "publicationYear 제거 재확인" 숙제는
  이로써 종결 — 단, 기존 프로젝트에서 z축/backfill/refresh에 연도를 쓰던 곳은
  `publicationDate` 기준으로 옮겨야 한다.

### SearchQuery — 현재 2필드로 고정 확정 (2026-08-03)

- `SearchQuery`는 `searchType: string`, `query: string` 두 필드만 유지한다 (추가 필드
  없음). 현재 스텁([SearchQuery.ts](../../src/collect/SearchQuery.ts))과 동일.
- Paper의 `collectedQuery: SearchQuery` 의존이 이로써 안정적으로 확정됨. 신빈이 추후
  필드를 추가하더라도 기존 2필드 이름/타입은 유지 전제.

## File 클래스 함수 구현

`common/File.ts`의 미구현(`throw`) 함수들을 실제로 채우는 작업. 위에서 Secret/Paper/
SearchQuery 필드를 확정했으니, 이들을 디스크에 읽고 쓰는 File 함수를 만든다.

### 전제 (001.md / 위 확정 사항에서)

- File은 interface가 아니라 concrete **static 클래스**다 (2026-08-02 회의, 저장 매체를
  Obsidian Vault로 확정). 인스턴스 없이 `File.메소드()`로 접근하고, `File.init(vault)`로
  vault 참조만 한 번 보관한다.
- Secret은 `apiKeys`가 private이라 직렬화 매핑을 스스로 소유한다(`toJSON`/`fromJSON`).
  File은 "평문 맵 ↔ 디스크 파일(JSON.stringify + vault I/O)"만 담당한다.
- Paper/SearchQuery는 필드가 전부 public이라 변환 함수가 불필요. 저장 형식을 우리가
  100% 통제하므로(아래 "버전 관리 안 함" 참고) 옛 스키마와의 매핑 계층도 필요 없다 —
  File이 Paper를 직접 직렬화/복원한다.

### File이 다루는 대상 (다이어그램 File 정의)

| 대상 | 파일 | 위치 | 접근 방식 |
|---|---|---|---|
| Secret | `Secret.json` | 플러그인 폴더 | `vault.adapter` |
| Subscriptions | `Subscriptions.json` | 플러그인 폴더 | `vault.adapter` |
| Paper | `<제목> (arxivId).json` **+** `.md` | 콘텐츠 트리(`PaperGraph3D/…`) | 일반 Vault API |

### 실제 저장 레이아웃 (현 Vault 조사 결과, schemaVersion:3)

기존 PaperGraph3D가 실제로 쓰던 형식. 샘플: `PaperGraph3D/2025/11/07/…(2511.05319).*`

- **경로**: `PaperGraph3D/YYYY/MM/DD/` — 날짜 폴더가 `publicationDate`(2025-11-07)와 일치.
- **파일명**: `<정제된 제목> (<arxiv 번호>).json` / `.md` (제목의 특수문자 정제됨).
- **`.json`** = 전체 데이터 원본. 래퍼 구조:
  ```jsonc
  {
    "schemaVersion": 3,
    "paper": { …paper 필드 + embedding 768차원… },
    "createdAt": 1785119131310,
    "updatedAt": 1785119131310,
    "readState": "unread"
  }
  ```
- **`.md`** = Obsidian용 노트. frontmatter + 본문:
  ```md
  ---
  title: "…"
  authors: [ … ]
  publicationYear: 2025
  publicationDate: "2025-11-07"
  citationCount: 0
  references: null
  readState: "unread"
  pg3d_sourceId: "arxiv:2511.05319"
  url: "https://arxiv.org/abs/2511.05319"
  ---
  <!-- pg3d:begin -->
  …초록…
  <!-- pg3d:end -->
  ```

### 구현할 함수

- `static init(vault: Vault, pluginDir: string): void` — vault/플러그인 폴더 참조 보관.
- `static readSecret(): Promise<Secret>` / `writeSecret(secret): Promise<void>`
- `static readSubscriptions(): Promise<Subscriptions>` / `writeSubscriptions(subs): Promise<void>`
- `static readPapersByYear(year: number): Promise<Paper[]>` — 해당 연도 폴더
  (`PaperGraph3D/<year>/`) 아래 모든 `.json`을 읽어 Paper 배열로 반환.
- `static writePaper(paper: Paper): Promise<void>` — `.json`과 `.md`를 **함께** 쓴다.

### File 확정 사항 (2026-08-03)

- **`.json`이 진실 원본(source of truth)**, `.md`는 Obsidian 표시용 뷰. 임베딩 벡터 등
  전체 데이터는 `.json`에만, `.md`엔 사람이 볼 frontmatter + 초록만 둔다.
- **파일 저장 위치 (2026-08-03 확정)**:
  - **Paper의 `.json` + `.md`**는 사용자가 Obsidian에서 봐야 하므로 콘텐츠 트리
    (`PaperGraph3D/YYYY/MM/DD/…`)에 둔다. 일반 Vault API(`vault.read`/`create`/`modify`)로
    다룬다.
  - **Secret.json / Subscriptions.json**은 우리(플러그인)가 관리하는 내부 파일이므로
    플러그인 폴더(`<vault.configDir>/plugins/papergraph3d/`)에 둔다. 이 경로는 일반 Vault
    API로 접근 불가하므로 `vault.adapter`(DataAdapter: `adapter.read`/`write`/`exists`)로
    다룬다. API 키가 노트 목록/동기화에 노출되지 않는 이점도 있다.
  - 플러그인 폴더 경로는 `main.ts`에서 `this.manifest.dir`를 `File.init()`에 넘겨 얻는다.
- **중복 제거 (2026-08-03)**: Secret/Subscriptions는 "플러그인 폴더 JSON 읽기/쓰기"라는
  동일 패턴이라 `readConfig`/`writeConfig` 공통 함수로 묶는다. Paper의 `.json`/`.md`는
  모두 콘텐츠 트리 텍스트 I/O이므로 `readVaultText`/`writeVaultText`(생성 or 수정 upsert)
  하나로 공용화하고, StoredPaperFile 래퍼는 `writePaper` 안에서 인라인으로 만든다.
  `JSON.parse`/`JSON.stringify`는 한 줄이라 별도 헬퍼로 빼지 않고 호출부에 인라인한다.
  백엔드(플러그인 폴더=`adapter` vs 콘텐츠 트리=Vault API)만 얇게 분리한다.
- **Secret.json 난독화 (2026-08-03 확정)**: Secret.json은 API 키가 담기므로 평문이 아니라
  변환해서 저장한다. 변환은 config 계층의 **선택적 인코딩 변환**으로 넣는다 — `writeConfig`에
  `encode`, `readConfig`에 `decode`를 옵션 인자로 주고, **Secret만 이 변환을 사용**한다
  (Subscriptions는 변환 없이 평문). 변환은 async 시그니처(`Promise<string> | string`)로 둬서
  나중에 WebCrypto 등 비동기 방식으로 교체해도 구조가 안 바뀌게 한다. 이렇게 하면 config
  공통 함수(`readConfig`/`writeConfig`)를 깨지 않는다.
  - **방식: 난독화, 키는 코드 하드코딩 (일단)**. 진짜 암호화가 아니라 "실수 노출/어깨너머"
    방지 수준. ⚠️ 플러그인은 `main.js`로 번들 배포되므로 하드코딩 키는 번들에서 추출
    가능하다 — 파일 유출 대비가 아님을 명확히 한다. 향후 진짜 기밀성이 필요하면 사용자
    패스프레이즈 기반(PBKDF2 → AES-GCM)으로 교체 (encode/decode 훅만 갈아끼우면 됨).
  - 함수명은 실체에 맞게 `obfuscate`/`deobfuscate`로 둔다(암호화가 아니므로).
- Secret 저장은 Secret의 `toJSON()`/`fromJSON()`을 거쳐 평문 맵으로 직렬화한다.
- **Paper 읽기는 연도 단위 일괄 (2026-08-03 확정)**: `readPaper(sourceId)`(단건) 대신
  `readPapersByYear(year)`로 바꾼다. 경로가 `PaperGraph3D/<year>/MM/DD/…`로 날짜에 의해
  결정되므로, 연도만 주면 그 폴더 아래 `.json`을 전부 읽으면 된다. → sourceId→경로 조회가
  필요 없어져 **인덱스(`buildIndex`/`index` Map)와 metadataCache 모두 불필요**. 구현은
  `vault.getFiles()`에서 `PaperGraph3D/<year>/` 접두 + `.json` 확장자로 필터해 읽는다.
- **Paper 파일명·.md 형식 = 기존 프로젝트 로직을 File 클래스에 통합 (2026-08-03 확정)**:
  기존 PaperGraph3D(`Desktop/Project/paperGraph/PaperGraph3D`)의
  `src/persistence/filename.ts`·`note.ts` 로직을 **별도 파일로 두지 않고 `File` 클래스의
  private static 메서드로 흡수**한다. 기존 vault 파일과 경로/형식을 100% 호환시키기 위함
  (규칙이 다르면 같은 논문에 다른 파일명이 생겨 중복).
  - 파일명 규칙(→ `File.resolvePaperPath`): 파일명 = `<정제한 title> (<localId>)`,
    경로 = `PaperGraph3D/<YYYY>/<MM>/<DD>/`. 정제 규칙(`\`·`:` → 공백/`_`, `$`·`{`·`}`
    유지 등)은 원본과 동일 — 실제 저장 파일명이 재현됨을 확인.
  - `.md` 형식(→ `File.renderMd`/`File.parseNote`): frontmatter + `pg3d:begin/end` 마커.
  - **새 Paper에 맞춘 적응 3가지**:
    1. `publicationYear` 필드 제거 → 폴더 연도·frontmatter 연도를 `publicationDate`에서 파생.
    2. 기존 `summary`/`futureDirections`는 새 Paper에 없어 관리 본문 = 초록만.
    3. `readState`는 완전히 제거 — `.json`/`.md` 어디에도 두지 않는다.
  - `parseUserBody`로 기존 `.md`의 **사용자 자유 본문(userBody)을 읽어 보존**한 뒤 다시 쓴다.
  - 즉 이 모든 헬퍼(`resolvePaperPath`/`renderMd`/`parseNote` 등)는 File 내부 private
    메서드다 — 새 파일/모듈을 만들지 않는다.
- **버전 분기는 안 하되 `schemaVersion` 필드는 남김 (2026-08-03 확정)**: 이전 버전을
  배포한 적이 없어 옛 프로그램이 수집한 파일과 현 파일이 섞일 일이 없다. 따라서
  `schemaVersion`으로 읽기 분기/마이그레이션을 구현하지는 않고, 저장 형식은 우리 형식
  하나로만 읽고 쓴다. 다만 **혹시 모를 향후 스키마 변경에 대비해 `schemaVersion` 필드
  자체는 저장 파일에 남겨둔다**(상수로 기록).
- **Paper 직렬화는 File이 직접 처리**: 위 결정으로 옛 스키마 매핑이 없어졌으므로 Paper에
  `toRecord`/`fromRecord` 같은 변환 함수를 두지 않는다. 저장은 `JSON.stringify({ …메타,
  paper })`, 복원은 `Object.assign(new Paper(), wrapper.paper)`로 충분하다.
- **우리 `StoredPaperFile` 형식 (2026-08-03)**: 관찰된 v3 래퍼에서 `readState`를 뺀다.
  `schemaVersion`은 향후 대비로 남긴다(단 읽기 분기는 구현 안 함, 상수로 기록). 최종
  형식은 아래와 같다:
  ```ts
  interface StoredPaperFile {
    schemaVersion: number; // 향후 대비용 상수. 현재는 분기/마이그레이션에 쓰지 않음
    paper: Paper;          // Paper 필드 그대로 (embedding 포함)
    createdAt: number;
    updatedAt: number;
  }
  ```
  - `readState`(읽음/안읽음)는 완전히 제거한다(2026-08-03). `.json`에도 `.md` frontmatter
    에도 두지 않는다. 이에 따라 frontmatter를 파싱해 값을 읽을 이유가 없어져, `.md` 처리
    헬퍼는 사용자 자유 본문만 추출하는 `parseUserBody`로 단순화(기존 `parseFrontmatter`/
    `parseScalar` 제거).

## File 클래스 public 함수 레퍼런스

`File`은 static 클래스다 — 인스턴스를 만들지 말고 `File.함수()`로 호출한다. `init` 한 번
호출 뒤 나머지를 쓴다. 파일 위치: Secret/Subscriptions는 플러그인 폴더(`Secret.json`/
`Subscriptions.json`), Paper는 콘텐츠 트리(`PaperGraph3D/YYYY/MM/DD/제목 (id).json` + `.md`).

### `init(vault: Vault, pluginDir: string): void`

- **용도**: vault와 플러그인 폴더 경로를 클래스에 등록한다. 다른 모든 함수의 전제.
- **호출 시점**: 플러그인 `onload`/`init`에서 딱 한 번. 이미 `main.ts`가 호출한다.
- **사용법**:
  ```ts
  File.init(this.app.vault, this.manifest.dir ?? '');
  ```

### `readSecret(): Promise<Secret>`

- **용도**: `Secret.json`(난독화 저장)을 읽어 복호화한 뒤 `Secret` 객체로 반환. 파일이
  없으면 빈 `Secret`.
- **사용법**:
  ```ts
  const secret = await File.readSecret();
  const key = secret.getKey('semanticScholar'); // 없으면 undefined
  ```

### `writeSecret(secret: Secret): Promise<void>`

- **용도**: `Secret`을 난독화해서 `Secret.json`에 저장(덮어쓰기). 누적하려면 먼저 읽어서
  키를 추가한 뒤 저장한다.
- **사용법**:
  ```ts
  const secret = await File.readSecret();
  secret.setKey('semanticScholar', 'sk-...');
  await File.writeSecret(secret);
  ```

### `readSubscriptions(): Promise<Subscriptions>`

- **용도**: `Subscriptions.json`(평문)을 읽어 `Subscriptions`로 반환. 파일이 없으면 빈
  `Subscriptions`. ⚠️ `secret` 필드는 저장에서 제외되므로 로드 후엔 비어 있다(필요하면
  `readSecret`으로 따로 붙인다).
- **사용법**:
  ```ts
  const subs = await File.readSubscriptions();
  const queries = subs.apis[0]?.querys ?? [];
  ```

### `writeSubscriptions(subscriptions: Subscriptions): Promise<void>`

- **용도**: `Subscriptions`를 `Subscriptions.json`에 저장. **`secret`은 제외**하고
  `{ updateTime, apis }`만 저장한다(API 키 평문 중복 방지).
- **사용법**:
  ```ts
  const subs = await File.readSubscriptions();
  subs.apis.push(myApi); // API.querys에 SearchQuery가 담김
  subs.updateTime = Date.now();
  await File.writeSubscriptions(subs);
  ```

### `readPapersByYear(year: number): Promise<Paper[]>`

- **용도**: `PaperGraph3D/<year>/` 폴더 아래 모든 `.json`을 읽어 `Paper[]`로 반환.
  sourceId 조회/인덱스 없이 연도 단위로 일괄 로드(시각화·재임베딩 등에서 사용).
- **사용법**:
  ```ts
  const papers2025 = await File.readPapersByYear(2025);
  ```

### `writePaper(paper: Paper): Promise<void>`

- **용도**: 논문 1편을 `.json`(전체 데이터, 진실 원본) + `.md`(Obsidian 뷰) 두 파일로
  저장. 경로는 `publicationDate`(폴더)와 `title`(파일명)에서 자동 계산. 재작성 시 기존
  `createdAt`과 사용자가 `.md`에 적은 자유 본문을 보존한다.
- **사용법**:
  ```ts
  const paper = new Paper();
  paper.title = '...';
  paper.publicationDate = '2025-11-07'; // 폴더 2025/11/07 결정
  paper.sourceId = 'arxiv:2511.05319';  // 파일명 뒤 (2511.05319)
  // ...나머지 필드 채우고
  await File.writePaper(paper);
  ```
- **주의**: `Paper`의 모든 필드를 채워서 넘긴다(특히 `title`/`publicationDate`/`sourceId`가
  경로·파일명에 쓰임).
